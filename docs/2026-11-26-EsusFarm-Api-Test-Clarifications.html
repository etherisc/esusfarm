1. Mandatory currency (no silent default to UGX)

The fulfillment note that currency defaults to UGX reflects the current API behaviour (PolicyIn has default="UGX"). The approved scope treats currency as mandatory.

Agreed: We will require currency on POST /policy and return a validation error if it is missing. We will deploy this to api-test and update the fulfillment document accordingly.

2. Only UGX policies on-chain for now

With currency routing (Part 2.3) and additional currency products (Part 2.4) not in scope, only UGX policies should be recorded on-chain against the single Amoy CropProduct.

Current behaviour (gap): The API validates multi-currency format, but on-chain sync does not block non-UGX. A policy with e.g. currency: "USD" can still be written to the UGX product (amounts are converted to token base units only).

Agreed: For POST /policy, on-chain recording only when currency is UGX. Other currencies → 422 with a clear message (multi-currency format can still be validated in tests without chain). Non-UGX on-chain recording awaits Part 2.3 / 2.4.

4. Decimal exactness vs USD vs UGX-only chain

  • Two-decimal rules (USD, ZAR, NGN, SZL): Validated at the API only until separate on-chain products exist; covered by automated tests and 422 cases — no on-chain USD policy in this phase.
  • On-chain decimal exactness (6 decimals on the token): Use currency: "UGX" and whole-unit amounts (e.g. premium 40,000 → 40,000,000,000 base units). Fractional UGX remains rejected by design.
  • We will adjust the Etherisc acceptance script and fulfillment test plan so the on-chain E2E path uses UGX only, not USD.
